## 現状と既知の課題（未対応のまま残しているもの）

1. **プレースホルダ値**：認証サーバーURL、`PRODUCT_SALT`、`OFFLINE_PEPPER`、CDN URL は仮の値。本番前に差し替えが必要。
2. **Pro判定がDSPに効いていない**：`src/audio-filter.cpp` の `apply_settings()` で `pro_scale` に代入している三項演算子が、未認証時も `1.0f` を返す。Pro/Standard の切り分けは現在 CMake の `MODEL600_PRO_EDITION`（物理的なコード除外）だけで成立している。認証状態をDSPやUIに反映するかは要設計。
3. **秘密値をクライアントに持つ設計**：オフライントークン検証のため、ソルトとペッパーがクライアント側バイナリに入っている（難読化のみ）。非対称署名（サーバー秘密鍵で署名し、クライアントは公開鍵で検証）へ移行するかを検討する。
4. **QSysInfo::machineUniqueId()**：OS再インストールや仮想環境で値が変わる。再認証フローの案内文言を要検討。
5. **OS干渉シールドのUI連携**：`ConflictShield::scan()` の結果を10秒カンペ測定モーダルに表示する部分は未接続。レジストリ書き換えの確認ダイアログ文言も含めて後で設計する。
6. **時計ズレSSL診断**：判定はエラーメッセージ文字列に依存している。Qt のバージョン差で文言が変わる可能性がある。

## 補足

- C++ と Worker のオフライントークンはバイト単位一致を確認済み（FNV-1a オフセット基底の修正後）。
- この領域を再開するときは、上記 2 と 3 を先に決めると後戻りが少ない。
